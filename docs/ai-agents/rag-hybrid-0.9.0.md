# 0.9.0 lane L3 results: hybrid retrieval, near-miss abstention, critic checks

The rules below were fixed in `docs/ai-agents/l3-prereg-0.9.0.md` (commit d04f19d) before any
number here was measured. Raw output: `docs/ai-agents/rag-hybrid-0.9.0.json`, regenerated by
`python -m ceap.rag.hybrid_eval` (add `--build` with `fastembed` installed to rebuild the caches).
Evidence class: deterministic, on the committed corpus and the 159-query C1 set.

## C2: hybrid retrieval

Plain idea: BM25 misses misspelt and reworded queries. A small embedding model (bge-small-en-v1.5)
and a cross-encoder reranker (ms-marco-MiniLM-L-6-v2), both local CPU models, can recover some of
them.

Formal: recall at 3 over the 124 positive queries, ranking only (no abstain gate), with a paired
bootstrap 95 % interval (10 000 draws, seed 0) of the difference against BM25.

| Variant | R@3 (k/124) | Wilson 95 % | R@1 | MRR | ΔR@3 vs BM25 [95 %] |
|---|---|---|---|---|---|
| bm25 | 108 | 0.80-0.92 | 0.69 | 0.796 | - |
| dense | 95 | 0.68-0.83 | 0.54 | 0.674 | -0.105 [-0.194, -0.016] |
| rrf | 112 | 0.84-0.94 | 0.65 | 0.782 | +0.032 [-0.032, +0.097] |
| bm25_rerank | 114 | 0.86-0.96 | 0.73 | 0.833 | +0.048 [+0.008, +0.097] |
| rrf_rerank | 116 | 0.88-0.97 | 0.75 | 0.848 | +0.065 [+0.016, +0.113] |

Most of the gain is on typos (BM25 23/30, rrf_rerank 29/30) and paraphrases (42/44 to 44/44).
Multi-hop is flat or worse (14/20 to 13/20).

Decision under the pre-registered rule: `rrf_rerank` and `bm25_rerank` clear the interval part of
the rule. They fail the second part, which says a default must run without a model download at
query time. Both need `fastembed` and about 100 MB of models for any query not in the cache.
**BM25 stays the default.** `ceap.rag.dense.HybridRetriever` is opt-in. Making the reranker the
default would need a packaged model dependency; that is an owner decision.

Note: ungated BM25 R@3 is 108/124. The 0.8.0 figure of 89/124 used the support gate, which also
drops weak correct hits.

## (a) Near-miss abstention: not fixed

The rule was chosen on the dev split only (odd-numbered extended ids, train, original negatives).
The candidate signals were BM25 support and the top cross-encoder score, and the objective was
answered-and-correct at 3 minus the negative leak rate. Dev chose the cross-encoder signal with a
threshold of -8.28.

| Split | Rule | Answered and correct at 3 | Near-miss leak |
|---|---|---|---|
| dev | chosen rule | 56/67 | 3/13 |
| dev | 0.8.0 gate (support 2.5) | 50/67 | 2/13 |
| held-out | chosen rule | 44/57 | **6/12** (0.25-0.75) |
| held-out | 0.8.0 gate | 42/57 | **1/12** (0.01-0.35) |

The dev-chosen rule does not generalise: on held-out it leaks six times as often as today's gate.
It is not adopted, and the 0.8.0 gate stays. The near-miss leak problem is still open: 3/25 pooled
(X01, X04, X11). These are on-domain questions whose wording overlaps a real section; neither
lexical support nor this cross-encoder separates them. The next step would be a labelled
"answerable" classifier, which needs more negatives than the 25 the set has.

## (b) Critic: deterministic statement checks

Plain idea: compare what a finding says with the numbers in the evidence it cites.
`ceap.agents.critic_checks` flags three problems:
- the finding's own citations disagree, or it cites a contradicting record;
- a number that no cited value of the named metric matches;
- a direction word ("improved", "narrowed") whose sign, given the metric's polarity, is the
  opposite of the cited change.

Each flag caps confidence (0.4 for a contradiction, 0.2 for a wrong number or direction) and is
recorded as a contradiction.

| Set | Before (detected) | After (detected) | False alarms after (clean cases) |
|---|---|---|---|
| existing (`ceap.eval.agents.critic_cases`) | 6/15 | 15/15 (0.80-1.00) | 0/10 |
| held-out v1 (`data/eval/critic_planted_heldout_v1.json`) | 6/15 | 15/15 (0.80-1.00) | 0/10 |

The held-out set was committed in d04f19d, before the checks were written, and was not edited
afterwards. The checks were developed against the existing set and the fault definitions. The
held-out set was run once on the finished checks and was not used to tune them. Caveat: the same
author wrote both the set and the checks, knowing the five fault kinds, so 15/15 is a regression
bar, not evidence that the checks generalise to model-written findings. Statements the checks
cannot parse pass unflagged.
