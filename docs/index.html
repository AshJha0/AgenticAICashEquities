AgenticAICashEquities

An enterprise-style Agentic AI platform that investigates, analyses and explains cash-equity trading and market behaviour. Ask "Why did our AAPL execution quality deteriorate between 14:00 and 15:00?" and it plans the investigation, pulls orders, fills, market data, order-book depth, venue statistics, technology telemetry and runbooks through MCP, computes every number with deterministic quant analytics, lets specialist agents interpret the evidence, has an independent critic challenge the findings, and writes an auditable report in which every claim points at an evidence record. Python · MCP · LLM · multi-agent harness · policy engine · RAG · FastAPI.

The LLM writes the explanation; the numbers come from deterministic systems. That boundary is enforced in code, not prose. The critic may only lower confidence. Findings whose evidence ids do not resolve are dropped before the report is written. The narrative is audited afterwards: every number must trace to the structured facts handed to the model and every evidence id must exist — the adversarial suite feeds the reporter a fabricated "0.0000 bps / 99.9% fill / EXEC-deadbeef" narrative and checks that all three are flagged. The evaluation numbers above were produced with the offline deterministic model; with a real model the same audits measure plan quality and narrative fidelity. The one false positive (S50) is a 200 bps drift inside a 3× volatility window scored as a secondary "price movement" — defensible, and reported rather than tuned away.

The architectural boundary

Python analyticsdeterministic computation: VWAP, IS, slippage, impact, attribution
MCPthe capability interface — the only way to reach data
Harnessthe control plane — agents never control the loop
Policy engineauthority: allow / deny / require approval, explained by rule
Evidenceauditability: every finding cites resolvable records

What's inside

Domain model

Framework-free frozen dataclasses and interfaces for the whole vocabulary — Task, Plan, PlanStep, Agent, Tool, ToolRequest/Result, Evidence (10 types), Finding, Quote, Trade, OrderBook, Order, Execution, ExecutionMetrics, PolicyDecision, repositories, reports. Nothing here imports MCP, an LLM SDK or a web framework.

Deterministic quant analytics

Pure NumPy functions with known-answer tests: VWAP/TWAP, Perold implementation shortfall (execution + opportunity legs, sign-correct for sells), arrival/VWAP/per-fill slippage, effective spread, permanent vs temporary impact, square-root impact estimate, realised and annualised volatility, drift/jump detection, depth, imbalance, stale/crossed-quote diagnostics.

Cause attribution

Window vs baseline scoring over a fixed catalogue — volatility, spreads, liquidity, venue degradation, technology latency, market-data anomaly, large-order impact, price movement — with documented thresholds, saturating scores, a materiality cut-off and guards (platform-wide rejects are not blamed on a venue; drift under high vol is discounted).

Synthetic cash-equity market

Seeded GBM mid path, tick-rounded NBBO with log-normal spread and size noise, Poisson prints across XNAS/ARCA/BATS/IEX/DARK1, five-level books, baseline and window VWAP parents with 30-second child slices, fills that cross the spread and walk the book, latency, rejects, engineering metrics/logs/deployments, positions and limits.

50 evaluation scenarios

Ten templates — normal, high volatility, wide spreads, low liquidity, venue degradation, technology latency, market-data anomaly, large parent order, unexpected price move, mixed market + technology — across AAPL, MSFT, NVDA, AMZN and META with structured ground truth; effects are injected only inside 14:00–15:00 so the prior hour is a clean baseline.

MCP servers

market_data (quotes, trades, book, statistics, reference), execution (parent/child orders, fills, TCA metrics, venue statistics, strategy config), risk (position, exposure, limit check, stress), engineering (logs, metrics, deployments, latency), knowledge (RAG). One definition serves in-process calls and a real FastMCP stdio server; annotations carry read-only, risk level and required capabilities.

MCP client & adapter

MCPClient abstraction with in-process and stdio implementations (official SDK). MCPToolAdapter turns discovered descriptors into domain tools; every invocation yields an evidence record with the arguments, correlation id and a SHA-256 digest of the payload, so the audit trail exists before any agent interprets the data.

Agent harness

Explicit state machine (CREATED → PLANNING → VALIDATING_PLAN → EXECUTING ⇄ AWAITING_APPROVAL → CRITIQUING → VALIDATING_EVIDENCE → FINALISING → COMPLETED), a policy-gated executor with bounded retry, per-step timeout and cooperative cancellation, asyncio.TaskGroup batching of independent tool calls, memory, tracing — and critic/validation/finalise appended whenever a plan omits them.

Planner

The model proposes a JSON plan restricted to the discovered catalogue; unknown tools, agents, step types and arguments are stripped and recorded, the dataset selector is injected only where the schema accepts it, unusable output falls back to a canonical plan, and the harness validates the result again — including a policy pre-check of every tool call before anything runs.

Specialist agents

Market (what happened in the market?), Execution (what happened to our orders?), Quant (what does the data show and why?), Risk (unusual exposure or limit usage?), Engineering (did technology behave normally?). Each reads the plan's tool outputs from memory, fetches anything missing through the same policy path, and returns findings with evidence ids plus CALCULATION evidence for its own derivations.

Critic

Deterministic checks first: every cited evidence id must resolve; an anomaly claim must be corroborated by the attribution score; cross-agent contradictions (quant blames technology, engineering says latency is normal) are flagged; single-evidence findings are capped. An optional LLM critique then runs and can only lower confidence.

Reporter with audits

Structured facts go to the model; the narrative comes back in the report's section structure. A number audit checks every figure against the facts (tolerant of rounding and percentage forms) and an evidence-id audit checks every cited id; discrepancies are attached to the report as warnings rather than silently accepted.

Policy engine & approvals

Ordered rules — deny list, read-only, required capabilities, argument guards, symbol universe, risk level — returning ALLOW / DENY / REQUIRE_APPROVAL with the rule that fired. Roles (viewer, trader, quant, engineer, admin) map to capabilities. Approval gateways: automatic (dev), queued with timeout (human decides via the API), deny.

RAG knowledge base

Eight enterprise documents — VWAP runbook, TCA methodology, venue configuration, trading limits, execution policy, market-data architecture, incident runbook, algorithm documentation — chunked by heading, embedded with a dependency-free hashed TF-IDF embedder, and exposed through the knowledge MCP server so retrieved passages become DOCUMENT evidence.

API, CLI, observability

FastAPI gateway with API-key auth and capability checks (202-accepted investigations, report, full result, trace, cancel, approvals), a ceap CLI (investigate · scenarios · evaluate · generate-data · serve), Prometheus text metrics, JSON-lines logging and an in-memory tracer that mirrors to OpenTelemetry when configured.

Adversarial suite

Prompt injection in the question, rogue plans with unknown/mutating tools and malformed steps, unparsable model output, a critic that tries to raise confidence, fabricated numbers and evidence ids in the narrative, oversized and out-of-universe tool arguments — each mapped to a control in the threat model.

Stage 2 ready

The roadmap — Research Agent → Alpha Analysis → Backtest Engine → Risk Agent → Critic → Human Approval — reuses the harness, policy engine, approval gateway and evidence model unchanged; the HUMAN_APPROVAL step type and queued approvals already exist.

Quick start

git clone https://github.com/AshJha0/AgenticAICashEquities && cd AgenticAICashEquities
python -m venv .venv && source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e ".[dev]"

# an investigation from the CLI — offline, deterministic model, ~1 s
ceap investigate "Analyse our AAPL execution between 14:00 and 15:00 and explain why implementation shortfall increased." --dataset T06

# the whole suite: unit, integration, MCP (incl. stdio), agent, adversarial, 50-scenario evaluation
pytest

# evaluation table against structured ground truth
ceap evaluate

# the API — docs at http://127.0.0.1:8000/docs
ceap serve
curl -s -X POST http://127.0.0.1:8000/investigations -H "X-API-Key: dev-trader-key" \
     -H "Content-Type: application/json" \
     -d '{"question": "Why did AAPL execution deteriorate between 14:00 and 15:00?", "dataset": "T05"}'

# real MCP over stdio: the five servers as subprocesses, 26 tools discovered
python scripts/run_stdio_mcp_demo.py

# use a real model (optional): pip install -e ".[llm]" and export ANTHROPIC_API_KEY=...
