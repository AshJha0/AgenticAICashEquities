AgenticAICashEquities

An enterprise-style agentic AI platform, built for learning and demonstration, that investigates and explains cash-equity execution quality and runs governed signal research. Ask "Why did our AAPL execution quality deteriorate between 14:00 and 15:00?" and it plans the investigation, pulls orders, fills, market data, order-book depth, venue statistics, technology telemetry and runbooks through MCP, computes every number with deterministic quant analytics, lets specialist agents interpret the evidence, has a critic challenge the findings, and writes a report in which every claim points at an evidence record. Current release: v0.9.0, the last planned release. Python · MCP · LLM layer (offline-provable; local open-weight model for evaluation) · multi-agent harness · policy engine · BM25 RAG (hybrid opt-in) · SQLite · FastAPI.

The LLM writes the explanation; the numbers come from deterministic systems. That boundary is enforced in code. The model gets strict output schemas, one pinned model per purpose and versioned prompts; the planner picks scope only from enumerated choices; the critic can only lower confidence and disputes a finding only through a named deterministic check; findings whose evidence ids do not resolve are dropped; the narrative is audited so every number traces to the structured facts and every citation to a real evidence record. The model-dependent paths are proven offline, with fake clients, scrubbed cassettes and wire contract tests over the real SDK. That proves the plumbing, not model quality: every metric that needs a real model is labelled UNKNOWN / NOT RUN LIVE.

The architectural boundary

LLMreasoning, planning, narrative — never a metric, never an evidence id
Python analyticsdeterministic computation: VWAP, IS, slippage, impact, attribution, signal statistics, backtest
MCPthe capability interface — the only way to reach data
Harnessthe control plane — agents never control the loop
Policy engineauthority: allow / deny / require approval, explained by rule
Evidenceauditability: every finding cites resolvable records

What's inside

Execution investigation

A question about a symbol and window is parsed deterministically, planned, run through MCP tools, interpreted by Market, Execution, Quant, Risk and Engineering agents, challenged by the critic and written up with evidence ids. 50 synthetic scenarios (10 templates x 5 symbols) carry structured ground truth.

Signal research (Stage 2)

Research, Alpha, Backtest, Portfolio risk, Critic, then human approval on the same harness: rank-IC statistics, an event-driven backtest with next-session fills, costs and a walk-forward split, a recomputed target portfolio checked against limits, and a deterministic verdict: PROMOTE, REJECT or (since 0.8.0) INCONCLUSIVE. The IC hurdle is fixed in advance (t >= 3.0 for a searched result), and two templates are calibrated to published moments. 30 synthetic research scenarios.

Deterministic quant analytics

Pure NumPy functions with known-answer tests: VWAP/TWAP, Perold implementation shortfall, slippage, effective spread, impact, volatility, depth and imbalance, cause attribution over a fixed catalogue, signal statistics, backtest, portfolio risk. Sharpe is on excess returns over the Ken French daily risk-free rate.

MCP servers

market_data, execution, risk, engineering, knowledge, research_data, alpha and backtest. One definition serves in-process calls and a real FastMCP stdio server; annotations carry read-only, risk level and required capabilities, which the policy engine reads.

LLM layer (0.6.0)

Fails closed: mock or anthropic, set explicitly outside dev. Model ids pinned in model_pins.toml; strict schemas; any fallback marks the result DEGRADED; CEAP_LLM_DISABLED is a kill switch. Since 0.8.0 the model names figures as placeholders that code renders, and prose that fails the number, id or citation audit is replaced by the template narrative. Offline proof only.

Agents and governance

The harness owns the state machine, retries, timeouts, approvals and the governance tail (critic, evidence validation, human approval); a plan cannot drop or reorder them. Every model input sits in a data block; case memory is bounded and off in evaluation. Since 0.8.0 each agent has its own tool allowlist, HIGH-risk tools always need a human approval from a different named person, and the policy fails closed without a symbol universe.

Retrieval with citations

Okapi BM25 (stdlib) over ten versioned, classified documents, with a measured chunking strategy and a minimum-support gate. The query is built by code, not the model. The reporter writes claims, then prose whose quoted spans are checked against the cited passages. Since 0.9.0 an opt-in hybrid retriever (dense embeddings, rank fusion, reranker) beat BM25 on recall at 3 in a held-out comparison, but BM25 stays the default because it needs no model at query time.

Deterministic ML

Change-point detection (robust z-scores, CUSUM, PELT onset), ridge signal combination with leakage tests, held-out calibration, and a pre-trade cost model. Every model is labelled with the hash of the synthetic generator it was fitted to and refuses a hash mismatch.

Evaluation

ceap evaluation-report prints capability, safety, robustness, cost (a labelled local estimate, not a bill) and live-only rows. A frozen golden set, a history file, drift monitors and scripts/check_docs.py in CI keep the documented numbers equal to the committed report.

Platform and persistence

SQLite (WAL, single writer, forward-only migrations) for tasks, results, approvals, staged orders and an HMAC-chained audit log that is never pruned; ceap db anchor records the chain head outside the database and ceap db verify-chain checks against it. CPU-bound tools run in a killable process pool under the server. Since 0.9.0 runs can be made durable (a step journal, CEAP_DURABLE_RUNS=1) and pending approvals expire on a sweep. FastAPI gateway with hashed API keys and roles, Prometheus metrics, JSON logs, OpenTelemetry-ready tracing.

Execution simulator (0.8.0)

A limit order book where passive orders fill only when traded through, impact caused by the bot's own fills, TWAP/VWAP/POV and Almgren-Chriss schedulers, child orders, an auction uncross, markouts and a predicted-versus-realised cost loop. Synthetic only.

Real-data study R5: VOID twice

A preregistered 12-1 momentum test on an approximately point-in-time S&P 500, free data only, prices in a git-ignored cache that is never committed. The preregistration was hashed before any data was read. Coverage failed its gate both times, so no statistic was computed and the pseudo-holdout is unspent.

Real-data study E1: NULL

Preregistered, hash-locked 49-industry momentum on free Ken French data. The 1990-2015 holdout was opened once and did not reject the null. One crash during the opening was ledgered and disclosed. A NULL is not evidence that the effect is absent.

Local model and stricter critic (0.9.0)

A local open-weight model behind the same client interface, with recorded cassettes that CI replays; a 200-attack injection corpus; a judge used only where it agrees with a reference. The critic now reads each finding's words against its cited numbers and direction.

Paper trading (synthetic)

Simulated next-close fills with the backtest's own cost model, an append-only HMAC-chained ledger, desk controls (pre-trade checks, kill switch in the environment or the database, NYSE calendar, reconciliation that fails the run) and a daily forward record. It tests operations and controls, not profitability.

AI and the LLM boundary

The model reasons, plans and writes; it never computes or invents a number. Code renders every figure, and prose that fails the number, id or citation audit is replaced by the template narrative. The harness owns governance: it strips any planner-supplied critic, validation or approval steps and appends its own. Hosted-model quality is UNKNOWN / NOT RUN LIVE.

The agent roster

Investigation: Planner, then Market, Execution, Engineering, Risk and Quant, then Critic and Reporter. Research: Planner, then Research, Alpha, Backtest and Portfolio risk, then Critic and Reporter. Only three agents call the model (planner, critic, reporter); the others are deterministic, and every finding must cite evidence ids.

Local open-weight model (0.9.0)

qwen2.5:7b-instruct through Ollama on one CPU-only laptop, seeds 1-3, replayed from cassettes: plan valid without repair 15/30, tool precision 161/161, recall 61/84; critic 35/45 planted faults; claims with a number outside their own fact keys 11/39 (0.10.0 re-audit); injection obeyed 3/40, all via the user question. The judge scores only hedging. The challenger (llama3.1:8b) comparison was not measured in 0.9.0. This describes a 7B model, not the pinned hosted models.

Quant

Two verticals, one discipline: execution-quality analytics (VWAP, implementation shortfall, slippage, impact, cause attribution) and signal-research analytics (rank-IC statistics, multiple-testing control, an event-driven backtest, portfolio risk). Pure functions with known-answer tests, run on seeded synthetic data.

Execution and TCA

Post-trade TCA measures an execution after the fact; since 0.8.0 ceap.execution also runs one: a limit order book where fills and impact come from the bot's own orders, TWAP/VWAP/POV and Almgren-Chriss schedulers, child orders, auctions, markouts and a predicted-versus-realised cost loop. Synthetic and seeded; nothing sends an order.

Research studies

Every study was preregistered and hash-locked before its data was read. R5 (stock-level 12-1 momentum) is VOID twice on coverage; E1 (49-industry momentum, Ken French data) is NULL on its 1990-2015 holdout; E2 explains why R5 could not pass on free data. None of this is evidence of an edge.

Evaluation

Mock LLM on synthetic data: 50 execution scenarios (primary cause 0.98), 30 research scenarios (verdicts 25/30), a signed golden set (research verdicts 13/15), and safety invariants held under 4 injected faults. scripts/check_docs.py keeps the documented numbers equal to latest.json.

Architecture

Layers from a framework-free domain package up through MCP servers, analytics, the harness, policy engine, evidence, persistence and the FastAPI gateway. The LLM writes the explanation; numbers and evidence come from deterministic systems, and each layer enforces a piece of that in code.

Real data and paper trading

R5 coverage was 75.1 % and then 74.9 % against a required 95 %, so no statistic was computed and the pseudo-holdout is unspent. The paper book runs on a synthetic feed, fills at the next close with the backtest's cost model, and has a forward record from 2026-11-09; no forward result yet. Paper orders only, behind two human approvals.

Learn

A guided course from the problem and a microstructure primer through TCA, attribution, the harness, MCP, agents, the critic, policy, retrieval, evaluation, Stage 2 research, paper trading, the execution simulator and the 0.9.0 local-model work, ending with a knowledge check.

Cookbook

Short recipes: run an investigation from the CLI, Python or the API, turn on approvals, compute TCA without any agent, add a scenario, tool, MCP server or agent, restrict a principal, read traces and run the evaluation.

Threat model

No live orders and no venue connectivity. The main risks are wrong or misleading conclusions, unauthorised data access, abuse of the agentic loop and, for the one write tool, unauthorised paper-order staging. Threats are listed with their controls and residual risks.

API

ceap serve starts the FastAPI gateway with interactive docs at /docs. The committed openapi.json is checked in CI so a route change is a visible diff, and a nightly Schemathesis job fuzzes the read-only operations. Hashed API keys and roles.

Quick start

git clone https://github.com/AshJha0/AgenticAICashEquities && cd AgenticAICashEquities
scripts/bootstrap.sh          # Windows PowerShell: .\scripts\bootstrap.ps1
source .venv/bin/activate     # Windows: .venv\Scripts\Activate.ps1

# an investigation (offline, deterministic mock LLM)
ceap investigate "Analyse our AAPL execution between 14:00 and 15:00 and explain why implementation shortfall increased." --dataset T06

# a signal research proposal (Stage 2)
ceap research "Does 12-1 momentum work on R01? Evaluate it out-of-sample with costs." --role quant

# the PR test tier, in parallel
pytest -n auto -m "not nightly"

# scenario evaluation and the full evaluation report (live-only rows print UNKNOWN)
ceap evaluate --suite all
ceap evaluation-report --quick

# paper trading on the synthetic feed
ceap paper run-day --date 2026-11-13 --db var/paper/paper.db

# the API, docs at http://127.0.0.1:8000/docs
ceap serve
