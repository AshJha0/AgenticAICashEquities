# OWASP LLM Top 10 mapping

This table maps each entry of the OWASP Top 10 for LLM Applications (2025 edition) to the
controls CEAP has in code and the tests that check them. It complements the threat list in
[threat-model.md](threat-model.md), whose `T` numbers are cited below. Where a control is partial
or planned, the row says so. Read "Gap" as "known and not yet closed", not as "not applicable".

Evidence class: every "Code" and "Tests" cell names a module or test in this repository at the
commit that added this file. Nothing here is measured against a live model; the adversarial
suite runs against the offline mock and assumes the model may obey an injection.

| ID | Risk | Controls in CEAP | Code | Tests | Gap |
|---|---|---|---|---|---|
| LLM01 | Prompt injection | Every untrusted surface (question, logs, deployments, retrieved documents, tool descriptions, case memory) reaches the model only inside a `<data>` block. The model's output is a plan or a narrative, never an action: the harness re-validates every plan step and the policy engine checks every tool call, including all symbol-bearing arguments at any depth (T1, T13, T30-T35) | `ceap.llm` data blocks, `ceap.harness.engine._validate_plan`, `ceap.policy.engine` | `tests/adversarial/test_surfaces.py`, `tests/unit/test_policy_r080_l2.py::test_a3_repros_are_denied` | Block hardening (NFKC, nonce tags) is plan step A8, another 0.8.0 lane |
| LLM02 | Sensitive information disclosure | Knowledge reads are limited by role (`classifications`); keys are held as salted digests and never logged; principals are labels, not key material; owner-scoped task reads (T25, T27) | `ceap.policy.engine._rule_knowledge_classification`, `ceap.api.auth` | `test_raw_key_absent_from_logs_errors_and_reprs_and_every_line_has_a_request_id`, `test_viewer_cannot_read_another_principals_task_auditor_can` | Broader redaction (A9) is another lane |
| LLM03 | Supply chain | MCP servers outside `CEAP_MCP_TRUSTED_SERVERS` are denied outright, even when they declare a tool read-only. Each server's tool catalogue is hashed at start-up; `CEAP_MCP_CATALOGUE_PINS` refuses start-up on a mismatch and `PinnedToolRegistry.verify_catalogue` refuses on drift. Model ids must be pinned (T20, T21) | `ceap.policy.engine._rule_untrusted_server`, `ceap.mcp.adapter.catalogue_hash`, `ceap.mcp.registry` | `test_a5_untrusted_read_only_tool_denied`, `test_a5_registry_refuses_pinned_mismatch`, `test_1_9_unpinned_model_is_refused` | Python dependencies are hash-locked (`requirements.lock`) but not signed; prompt-hash verification is A15 |
| LLM04 | Data and model poisoning | No model is trained or fine-tuned here. Case memory is written only by the harness after a human decision, append-only and off in evaluation (T35) | `ceap.harness` case memory | `test_3b7_*`, `test_surface_case_memory` | Knowledge-ingestion screening and effective-date filtering are A17 |
| LLM05 | Improper output handling | Model output is parsed against a schema and sanitised; numbers and evidence ids in the narrative are audited; findings must cite values that exist at the cited path (T4, T36) | `ceap.agents.reporter`, `ceap.harness` validation | `test_fabricated_numbers_and_evidence_ids_are_flagged`, `test_3b4_*` | Typed placeholders and prose suppression are A1/A2 |
| LLM06 | Excessive agency | Each agent runs with its own capability set and tool allowlist, intersected with the principal's; no agent holds `tools:write`. HIGH-risk tools always need a human approval decided by a different named person; admins cannot decide approvals. The approver sees the exact arguments and their content hash, and the hash is re-checked just before the tool runs (T2, T11, T17, T24) | `ceap.policy.agents`, `ceap.policy.engine._rule_risk_level`, `ceap.policy.approvals.bind_to_content`, `ceap.api.auth` subjects | `test_a16_*`, `test_a4_*`, `test_a13_same_person_two_keys_blocked_by_four_eyes`, `test_a14_*`, `test_1_3_*` | Subject mapping is opt-in per key; an unmapped key is still its own principal |
| LLM07 | System prompt leakage | System prompts hold no secrets or credentials; authority lives in code (policy, harness), so a leaked prompt grants nothing | `ceap.llm` prompts, `ceap.policy` | `tests/adversarial/test_surfaces.py` (invariants hold when the model obeys) | None known |
| LLM08 | Vector and embedding weaknesses | Retrieval is lexical over a local, versioned knowledge base; each chunk is its own data block with a citation id; classification filter applied before retrieval (T33) | `ceap.rag` | `test_surface_rag_documents` | Superseded-version rejection is A17 |
| LLM09 | Misinformation | Numbers come from deterministic analytics; the critic cannot change a confidence by itself; unsupported findings are dropped; evaluation reports say NOT RUN LIVE where nothing was measured (T4, T5, T16) | `ceap.analytics`, `ceap.agents.critic`, `ceap.evaluation_report` | `test_every_finding_cites_resolvable_evidence`, `tests/agent/test_critic_and_reporter.py` | Live-model measurement is WS-B |
| LLM10 | Unbounded consumption | Per-step timeout, task deadline, bounded retries, investigation semaphore, request-size limits; the policy engine bounds argument size, depth, item count and page `limit` (after numeric coercion) (T6, T15, T29) | `ceap.harness.executor`, `ceap.api`, `ceap.policy.engine._size_problem` | `test_tool_timeout_is_reported`, `test_request_limits_body_question_notional_and_pagination`, `test_a3_repros_are_denied` | Default-on, race-free token and cost budgets are A10 |
