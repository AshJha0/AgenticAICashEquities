# Cash Equities Agentic Platform (CEAP)

[![CI](https://github.com/AshJha0/AgenticAICashEquities/actions/workflows/ci.yml/badge.svg)](https://github.com/AshJha0/AgenticAICashEquities/actions/workflows/ci.yml)

> **Read this first.**
> - Every dataset **committed** here is **synthetic data** generated by the repo: the 50 execution
>   scenarios, the 30 research scenarios, the golden sets and the paper-trading feed. The
>   exceptions are free public data read for two research studies: R5 (real daily prices from a
>   git-ignored local cache, published **VOID** twice, no statistic computed) and E1 (Ken French
>   49-industry returns, raw-file hashes recorded, result **NULL**). Small public reference files
>   (S&P 500 membership changes, Ken French factors and risk-free rate) are committed with
>   attribution under `data/reference/`.
> - **Nothing trades**: the only write path stages **paper orders**, behind two human approvals
>   from two different people.
> - **No hosted-model numbers.** No test, demo or CI job calls a hosted model; those paths are proven
>   offline (fake clients, wire contracts) and labelled UNKNOWN / NOT RUN LIVE. 0.9.0 adds runs
>   against a **local open-weight model** (Ollama, `qwen2.5:7b-instruct` with
>   `llama3.1:8b-instruct-q4_K_M` as challenger); CI replays their recorded cassettes. Results:
>   <!-- source: docs/evaluation/local_model/qwen2.5_7b-instruct.json --> qwen2.5:7b on one laptop, pooled over 3 seeds from replay: plan valid 15/30 (0.50), tool precision 1.00, recall 0.73; critic 35/45 (0.78); 0/39 untraceable numbers reached a report; end-to-end golden slice not measured (the 6/9 and 3/3 first published were mock-fallback output, withdrawn 2026-11-12); injection obeyed 3/40 (all via the question); judge enables only `hedged` (kappa 1.00); challenger not measured (known issue) (`docs/evaluation/local_model/README.md`).

An agentic AI platform that investigates, analyses and explains cash-equity trading and market
behaviour. Ask it:

> *"Why did our execution quality for AAPL deteriorate between 14:00 and 15:00 yesterday?"*

and it plans an investigation, pulls orders, fills, market data, order-book depth, venue statistics,
technology telemetry and runbooks through **MCP**, computes every number with **deterministic quant
analytics**, lets specialist agents interpret the evidence, has an independent **critic** challenge
the findings, and writes an **auditable report** in which every claim points at an evidence record.

Or ask it (Stage 2, signal research):

> *"Does 12-1 momentum work on this universe? Evaluate it out-of-sample with costs and propose whether to promote it."*

and the same harness runs **Research → Alpha → Backtest → Risk → Critic → Human Approval**: rank-IC
statistics, an event-driven backtest with a cost model and a walk-forward split, portfolio limits and
stress on a recomputed target portfolio, a deterministic verdict with flags, and a human approval
gate that sees the assessment. An admin can ask for a second approval and a *paper* order-staging
step behind the platform's only non-read-only tool.

```
Python 3.11+  ·  MCP  ·  LLM (Anthropic, local Ollama for evaluation, or offline mock)  ·  multi-agent harness  ·  FastAPI  ·  RAG  ·  policy engine  ·  OpenTelemetry-ready
```

**Current release: v0.9.0**, the last planned release (details in [CHANGELOG.md](CHANGELOG.md)).

## The boundary

The architectural boundary is enforced in code, not only described:

| Concern | Owner | Never |
|---|---|---|
| Reasoning, planning, narrative | LLM | computes a metric, invents an evidence id |
| VWAP, IS, slippage, impact, volatility, liquidity, attribution | `ceap.analytics` (pure Python/NumPy) | – |
| Capability interface | MCP servers + `MCPToolAdapter` | – |
| Control plane (state machine, retry, timeout, approval, trace, run journal) | `ceap.harness` | lets an agent control the harness |
| Authority (schema and symbol checks on every argument, per-agent tool allowlists, four-eyes by named person on HIGH risk, untrusted MCP servers denied) | `ceap.policy` | lets a capability skip the approval for a HIGH-risk tool |
| Auditability | `Evidence` / `Finding` | a finding without resolvable evidence survives validation |

The model names figures as typed placeholders and code renders them; a narrative that fails the
number, evidence-id or citation audit is replaced by a template. Details:
[docs/ai-agents/ai-agents.md](docs/ai-agents/ai-agents.md).

## Quick start

```bash
scripts/bootstrap.sh          # Windows PowerShell: .\scripts\bootstrap.ps1
source .venv/bin/activate     # Windows: .venv\Scripts\Activate.ps1

# 1. run an investigation from the CLI (offline, deterministic mock LLM)
ceap investigate "Analyse our AAPL execution between 14:00 and 15:00 and explain why implementation shortfall increased." --dataset T06

# 2. run the API and open http://127.0.0.1:8000/docs
ceap serve
curl -s -X POST http://127.0.0.1:8000/investigations -H "X-API-Key: dev-trader-key" -H "Content-Type: application/json" \
     -d '{"question": "Why did AAPL execution deteriorate between 14:00 and 15:00?", "dataset": "T05"}'

# 3. run a signal research proposal (Stage 2) - momentum on the R01 universe, or the regime-break dataset R04
ceap research "Does 12-1 momentum work on R01? Evaluate it out-of-sample with costs." --role quant
ceap research "Does momentum survive the regime break on R04?"
ceap research "Promote momentum on R01 and stage the orders" --stage-orders --role admin   # two approval gates, paper orders

# 4. run the tests (PR tier, in parallel; plain `pytest` runs every tier)
pytest -n auto -m "not nightly"

# 5. evaluate against the ground truth: 50 execution scenarios, 30 research scenarios
ceap evaluate --suite all

# 6. the whole evaluation table (capability, safety, robustness, cost; live-only metrics print UNKNOWN)
ceap evaluation-report --quick
```

The research API flow (a quant proposes, an approver decides; with `CEAP_AUTO_APPROVE=false` the
proposal waits in `/approvals`):

```bash
curl -s -X POST http://127.0.0.1:8000/research -H "X-API-Key: dev-quant-key" -H "Content-Type: application/json" \
     -d '{"question": "Does 12-1 momentum work on R01? Evaluate it out-of-sample with costs."}'
curl -s http://127.0.0.1:8000/approvals -H "X-API-Key: dev-approver-key"            # shows the assessment + target portfolio
curl -s -X POST http://127.0.0.1:8000/approvals/<id> -H "X-API-Key: dev-approver-key" -H "Content-Type: application/json" \
     -d '{"approved": true, "comment": "promote"}'
curl -s http://127.0.0.1:8000/research/<task_id>/report -H "X-API-Key: dev-quant-key"   # kind=research, proposal.verdict
```

The LLM layer **fails closed**. `CEAP_LLM_PROVIDER` is `mock` (the dev default: a deterministic
offline client) or `anthropic` (needs the `llm` extra and `ANTHROPIC_API_KEY`); outside dev it must
be set explicitly, and `anthropic` without a working client refuses to start instead of quietly
using the mock. Model ids are pinned in `src/ceap/llm/model_pins.toml`. Any fallback (a repair
retry, a canonical plan, a templated narrative) is recorded and marks the result `DEGRADED`;
`CEAP_LLM_DISABLED=true` forces the deterministic path everywhere. The local Ollama client is used
only by the evaluation runners and needs `CEAP_LOCAL_MODEL=1` (COOKBOOK recipe 49).

The bootstrap scripts install `.venv` from `requirements.lock`, a universal hashed lock that
installs on Windows and Linux with Python 3.11, 3.12 and 3.13 ([versions](docs/testing/python-versions.md)). Every environment variable and every CI
check is listed in [docs/configuration.md](docs/configuration.md).

## Results, stated plainly

All of these measure the deterministic pipeline on synthetic data unless the line says otherwise.
None says anything about real markets or about a hosted model's quality.

- **Execution investigations:** <!-- metric: capability.primary_accuracy -->0.98 primary-cause accuracy over 50 scenarios (<!-- metric: capability.coverage -->0.98 ground-truth coverage, <!-- metric: capability.false_positive_rate -->0.06 false-positive rate). The test bar is 90 % primary accuracy and coverage.
- **Research proposals:** <!-- metric: capability.research_verdict_accuracy -->0.8333 verdict accuracy over 30 scenarios in the committed `latest.json`. A re-run on the 0.9.0 branch with the critic change gave 23/24 clear verdicts (<!-- source: docs/ai-agents/rag-hybrid-0.9.0.md --> lane L3 notes; RS02 missed for COST_DRAG); the regenerated 0.9.0 `latest.json` keeps 0.8333.
- **Null control:** the 500-seed null sweep at the a-priori hurdle (IC t >= 3.0 for a searched result) found 0 false PROMOTEs (simulation; <!-- source: docs/research/null_sweep_per_seed.json --> per-seed vector committed).
- **Critic (0.9.0):** deterministic statement checks raised planted-fault detection from 6/15 to 15/15 on the existing set and on a held-out set committed before the change, with 0/10 false alarms on each (synthetic; <!-- source: docs/ai-agents/rag-hybrid-0.9.0.md --> details; re-checked after the numeric-rounding fix with `python -m ceap.agents.critic_planted`). The same author wrote the planted sets and the checks, so this is a regression check, not an independent measure.
- **Retrieval (0.9.0):** a cross-encoder reranker beat BM25 on R@3 by +0.065 (paired 95 % CI +0.016 to +0.113) over 124 queries (<!-- source: docs/ai-agents/rag-hybrid-0.9.0.md --> details). BM25 stays the default because the reranker needs a model at query time, the rule fixed before the run. Near-miss abstention is still open: 3/25 near-miss negatives leak.
- **E1, real data:** 49-industry momentum, preregistered and hash-locked; holdout 1990-2015 opened once: **NULL** (net of 10 bps, Newey-West t 1.16 against 1.645; <!-- source: docs/research/e1/result_holdout.json --> result file).
- **R5, real data:** **VOID** twice: point-in-time coverage <!-- source: docs/research/result_momentum_2026-11.md --> 75.1 % and then <!-- source: docs/research/result_momentum_2026-11-v2.md --> 74.9 % against a required 95 %, because free sources lack delisted names. No statistic was computed; the pseudo-holdout is unspent. Why stock-level R5 could not pass on free data: [docs/research/e2_why_r5_could_not_pass.md](docs/research/e2_why_r5_could_not_pass.md).
- **Paper forward log:** a daily job on synthetic data. The record restarted on 2026-11-12 on branch `forward-log-v2` after the first one failed (see CHANGELOG, Unreleased); branch `forward-log` is kept as a disclosed false start. It is not yet a daily record until scheduled sessions appear on the new branch. It checks operations and controls, not profitability; telling a true Sharpe of 1 from 0 needs about 1980 sessions (<!-- source: tests/unit/paper/test_forward_and_ledger.py --> power formula, LEARN section 18a). Forward result: UNKNOWN.

## What 0.9.0 adds

Six parallel lanes integrated on one branch; the full list, with every number and disclosure, is in
[CHANGELOG.md](CHANGELOG.md). Plan and per-step status: [docs/review/2026-11-09/PLAN.md](docs/review/2026-11-09/PLAN.md).

- **Local model evaluation:** `ceap.llm.ollama.OllamaLLMClient` behind the same `LLMClient` interface
  and Pydantic validation, recorded cassettes replayed in CI, a 200-attack prompt-injection corpus,
  a rubric judge enabled per dimension only when Cohen's kappa > 0.6, a challenger-model view for
  approvers (off by default) and AI SLO monitoring. See [docs/ai-agents/ai-agents.md](docs/ai-agents/ai-agents.md).
- **Critic and retrieval:** deterministic `contradicted`, `numeric_mismatch` and `direction_mismatch`
  checks (`ceap.agents.critic_checks`, recorded in `assessment["flags"]`); opt-in hybrid retrieval
  (dense embeddings, rank fusion, reranker) over a hashed model cache.
- **Research:** E1 (NULL) and E2 (above); a 500-name synthetic universe; delisting sensitivity on
  the real-data momentum book.
- **Paper and execution:** closing-auction MOC cap, lot sizes, an order-book engine for fill costs,
  a sigma price band, halts (on by default), dividends as cash events, integer micro-dollar money in
  ledger bodies (v2; 0.8.0 rows verify unchanged).
- **Platform:** the harness engine split into mixins, durable runs (step journal, resumable
  approvals), an approval TTL sweep, a runbook and alert rules, chaos tests, a paper-day replay
  gate, stricter API keys outside dev (breaking for short raw keys), a two-stage Docker image.
- **Engineering:** `mypy src` clean, Windows CI, supply-chain workflows (Dependabot, CodeQL,
  Scorecard, SBOM, signing), nightly mutation testing with a ratchet, benchmarks gate, checked-in
  OpenAPI, ADRs, a learning path, glossary and exercises.

## Architecture in one picture

```
User → API (FastAPI, API keys, RBAC) → AGENT HARNESS (plan → validate → execute ⇄ approve → critique → validate evidence → report)
     → agents (investigation: market, execution, quant, risk, engineering; research: research, alpha, backtest, portfolio risk; critic, reporter)
     → ToolRegistry → MCP servers (market_data, execution, risk, engineering, knowledge, research_data, alpha, backtest)
     → deterministic quant analytics
```
